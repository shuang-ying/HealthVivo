# 活力记录 · 手机 0.14.1 / 手表 0.7.1

本版把手机与手表之间的蓝牙连接重写为独立的持久化直连实现：单特征 GATT 读写、CRC32 校验的分帧传输、首次登记后自动认证、双端自动重连，手表端另有广播看门狗。协议见 [LINK_PROTOCOL.md](docs/LINK_PROTOCOL.md)，实现与验证状态见 [LINK_IMPLEMENTATION.md](docs/LINK_IMPLEMENTATION.md)，使用说明见 [WATCH_GUIDE.md](docs/WATCH_GUIDE.md)。手表协议测试 40 项、手机 JVM 测试 49 项通过；已在真机（X80 + GT2）验证完整同步保存确认，长期后台行为仍待验证。GitHub 发布说明见 [GITHUB_RELEASE.md](docs/GITHUB_RELEASE.md)，其中三套软件流程对应旧扩展版本；新版本尚未发布。

通过用户录入或选择的食物照片、文字、体重与运动数据，计算热量参考值和记录趋势。手机独立记录、BMI、手动体脂率与 AI 建议继续可用；手表通过手机原生 BLE 客户端和 BlueOS 原生服务同步，不读取 vivo 健康数据库。

手表看板：iQOO WATCH GT2 / BlueOS 3 显示步数、运动、热量、三餐、体重、目标和手机 AI 建议，并可按天离线查询。只在手机点击“更新到手表”或手表主页底部点击“获取更新”后同步，按日期只更新新增和修改的摘要；保存记录和切换日期不自动同步。首次搜索并选择手表，连接凭据自动保存在两端；手机前台服务维护连接并按 1、2、4、8 秒递增重试（上限 30 秒），手表端每 3 秒检查一次广播与服务，无人连接时重新请求广播、服务失效时重建服务，因此手机随时可以重新连上。手表会话失效时手机会在同一条蓝牙链路上重跑握手，不重建物理连接。系统回收/挂起仍可能中断；真机长期后台表现尚未验证。使用说明见 [WATCH_GUIDE.md](docs/WATCH_GUIDE.md)。

## 可以使用的功能

- 个人资料：年龄、身高、当前体重、目标体重、公式性别参数、保持/减脂/增重目标；已取消活动水平。
- 能量卡片同时列出当天消耗参考与登记摄入，绿色／红色差值仅等于消耗参考减登记摄入；没有登记食物的合计为 0。消耗仍按静息加已记录净活动估算。
- 体重与 BMI 为独立可拖动卡片；两列标题与数值对齐，红黄绿数轴和箭头标出当前 BMI，超出范围显示到参考边界所需增／减重公斤数，正常时不显示。
- 首页目标体重与差值显示；可独立修改 / 清除目标，不改写已记录体重。
- 首页AI每日建议：共用API，饮食、运动、步数、体重、资料或目标保存成功后自动生成 / 更新；按日保存在手机，可手动重新生成。
- 每日总步数单独录入、更新、补录、删除和 CSV 导入；步长可选，缺失时只保存步数。
- 体重：按天录入/更新、趋势图、删除、CSV 导入；体重旁显示 BMI 及成人参考分类。
- 体脂率：用户手动录入测量值，按日更新、删除、趋势和备份；首页独立可拖动卡片，个人资料中也可填写。依据年龄和性别显示参考正常、偏低、偏高，新增颜色数轴与当前值箭头，两端使用相同范围；不由 BMI 推算。
- 三餐与加餐：209 种可离线搜索的基础食物、11个分类，自定义食物库，克数计算，编辑与删除。食物保留生熟状态、FDC编号和营养来源。
- 本地文字匹配：例如“熟米饭150g，香蕉100g”；对未知食物、模糊份量不会自动猜测。
- 拍照/选图及复杂文字 AI 识别：配置通用接口后点击发送，只发送本次输入；结果经用户检查食物、份量与热量后保存。
- 运动：填写名称，选择有氧/无氧，按时间、距离或组数记录；可补充次数、负重、总时长及休息等说明。
- 运动热量支持本地 MET/平地步行跑步距离公式和 AI；与三餐共用 API 配置，确认结果后保存。条件不足时保存为待估算，组数不会自动换算为热量。
- 74个运动/强度类型可搜索、按8个分组浏览，选择后带入名称、分类和步数重叠标记；保留2024 Compendium来源及编号。
- AI配置：输入服务地址和密钥后自动读取模型列表，支持搜索选择、重新检测、失败时手动填写；只检测列表，不调用模型生成。
- 靛蓝 / 白 / 浅灰主题、简化的固定页头、自适应启动图标、42个矢量图标、圆角卡片、分类筛选、摄入餐次进度和体重面积图。支持系统深色模式、大字体自动换行和指标卡片调整布局，各页面滚动位置独立重置。
- 步行/跑步可标记为已包含在当天总步数中，合并时取两种估算较大值，避免直接相加；该近似可能漏算运动以外的步行。
- 导出 JSON 记录备份，API 密钥不会进入导出文件。此版尚无 JSON 备份恢复入口，导出文件也可供后续迁移使用。

二级录入、餐次详情、食物选择、运动选择、AI模型选择及配置均使用完整页面：返回按钮、滚动内容和固定底部主操作；保存错误显示在底部按钮上方。食物和运动选择采用固定360dp高度的选择框，在框内连续滚动全部搜索结果，无上一页 / 下一页按钮；搜索或切换分类时回到列表顶部。

首页模块可长按右侧六点手柄上下拖动，靠近上下边缘可滚动到其他模块；顺序保存于本机。首页已移除重置按钮与独立排序提示，日期切换合并到紧凑顶栏，模块使用其余可用显示空间。排序不会调用AI。

## 使用顺序

1. 打开“我的 → 编辑个人资料”，填写真实资料与目标体重；首页“目标体重”卡片也可单独设置或清除目标。
2. “饮食”首页只展示早餐、午餐、晚餐及各餐已记录食物。点击某一餐进入详情，再点“添加食物”或右上角＋，选择食物库或照片 / 文字识别；也可手动录入。加餐入口在餐次详情中，旧加餐记录保留。
3. “运动”首页只展示已添加的运动，右上角＋打开新增页面；点击卡片查看详情、删除，编辑图标修改。每日步数从首页步数卡片或“录入／修改每日步数”按钮填写，也可通过“快速记录 → 步数”进入；“趋势”中记录体重。运动填写后点击本地公式或 AI，核对估算再确认保存；也可先存待估算记录。
4. 在“我的”页右上角设置或“我的 → AI 服务”填写 HTTPS 服务地址（例如基础地址 `/v1`，或完整 `/chat/completions` 地址）和自己的密钥。停顿约1秒自动检测模型；点击“选择模型”搜索，也可手动填写。保存后供三餐与运动共用。
5. 用文字描述或照片点击“AI 识别这一餐”，检查预览结果后确认入账。未配置 API 时，离线记录和食物库照常可用。
6. 配置API后，保存饮食 / 运动 / 步数 / 体重 / 体脂率 / 资料或目标会自动更新对应日期的建议，发送资料（含目标体重）、当天餐食/活动及近7日体重、体脂率摘要。连续保存合并，失败不影响记录；也可首页手动重新生成。界面只展示简短的吃饭与锻炼建议，结果按日保存在手机，不自动改写记录，也不自动同步手表。

图片识别需要支持图像输入的模型；纯文本模型可用于饮食文字和运动。接口采用兼容 Chat Completions 的 messages/text/image_url 结构；不支持所有供应商的私有协议。尚未使用真实服务商/密钥进行在线联调。食物请求仅发送本次文字/照片，运动请求仅发送本次运动与当时体重，不发送年龄、身高或历史记录。每日建议会在保存或删除健康记录后自动更新，也可按钮重试；按界面提示发送资料、对应记录日摘要与该日之前7日内的体重记录，使用同一API。

模型检测依照 [模型列表协议](https://developers.openai.com/api/reference/resources/models/methods/list)，使用同一个基础路径下的 `GET /models`，仅向用户指定服务发送认证头，不发送健康记录或在正文/URL携带密钥；不跟随重定向。模型列表不保证支持图片或本应用请求格式，需按服务商说明选视觉模型。未开放列表或认证失败时有提示，仍可手动填写。更换域名会清空当前表单中的密钥输入，取消则保留此前已保存配置。

## CSV 上传格式

UTF-8 编码，日期 YYYY-MM-DD；最多 1 MB / 1000 条记录。选择文件后确认导入。

体重：

```csv
date,weight_kg
2026-10-11,70.5
2026-10-12,70.0
```

运动：

```csv
date,name,minutes,kcal
2026-10-12,步行,30,100
```

每日步数（步长列可省略，也可留空）：

```csv
date,steps,step_length_cm
2026-10-11,0,
2026-10-12,6000,70
```

列名固定。体重和步数文件拒绝重复日期；与已保存的同日记录相比，新文件值会更新原值。同一运动文件再次导入使用稳定记录 ID，不重复累加；同一文件中的两条相同运动仍可保留为两条。旧运动 CSV 热量口径未知，只保留记录，不计入净消耗，需编辑后重新估算。任何一行无效均拒绝整个文件，避免部分入账。

## 计算与食物来源

公式、运动估计、食物来源和参考值边界见 [CALORIE_MODEL.md](docs/CALORIE_MODEL.md)。209 种基础食物不是完整中国菜谱，复杂菜品及油、酱料仍需根据实际份量填写或识别后修正。

食物库已作为 foods.json 打包，无需账号、API 或联网查询。生成脚本 scripts/generate-food-catalog.py 从官方 USDA SR Legacy CSV 压缩包提取数值与来源编号，不由语言模型生成营养数值。

运动库由 scripts/generate-exercise-catalog.py 核对 [2024 Adult Compendium](https://pacompendium.com/) 官方条目后生成，选择项保存在 scripts/exercise-selection.json。JSON与计算模块使用同一组生成的数据，扩充时不能任意编写MET值。跑步/步行之外的距离或无时长组数不会强行套用距离公式。

## 构建与安装

Android Studio 打开 android；Gradle 使用 JDK 17，API 36 / Build-Tools 36.0.0。

```powershell
./scripts/build-android.ps1
./scripts/build-watch.ps1
./scripts/build-android.ps1 -Install
./scripts/build-android.ps1 -UnitTests
./scripts/build-android.ps1 -DeviceTests -Install
```

默认脚本只编译和打包，不运行测试；-UnitTests / -DeviceTests 为显式测试选项。

当前产物 artifacts/vitality-phone-0.14.1.apk、artifacts/health-vivo-watch-0.7.1.rpk。包名保持兼容，应用名“活力记录”。本次不改变数据库版本4，保留旧记录、加密 API 配置、日期版本账本和手表缓存；新旧蓝牙连接信息分开保存（新键 `link_connection` / `link_secret`、手表 `fitness.link.identity.v1`），升级后需要一次首次连接，不需 ovpkg。专用协议测试：`node --test watch/test/link-wire.test.mjs watch/test/link-server.test.mjs`；跨语言向量：`node scripts/generate-link-vectors.mjs`；手机端 `./scripts/build-android.ps1 -UnitTests`。脚本默认仍只构建。

本机数据库为 fitness-local.db，当前版本4；从0.3.0的数据库版本1迁移到版本2，保留个人资料、体重、三餐、自建食物和历史运动，移除活动系数并增加步数表。旧手填运动热量口径未确认，不参与净消耗；旧 MET 值保留，步行/跑步默认标记包含在总步数中，可编辑。没有破坏性迁移或清空数据操作。旧手机采集原型保留在 archive；手表现为手机数据看板。健康数据保存在应用私有目录，关闭 Android 自动备份；API 密钥用 Android Keystore 加密。应用不会读取计步、位置或其他 App 的私有数据。

0.7.0从数据库版本2升级到3，仅增加可空的目标体重字段，原API加密别名保留，已有健康记录不会重新计算或改写。AI建议单独存于本机缓存，保留最近14个记录日，不纳入JSON健康记录备份。真机测试脚本采用覆盖安装及直接 instrumentation，不通过会卸载主应用的测试编排流程运行。0.5.2历史验证见 artifacts/verification-0.5.2.md；0.6.0按用户要求只开发、构建和安装，不运行测试，页面改版说明见 artifacts/delivery-0.6.0.md；0.6.1选择框调整见 artifacts/delivery-0.6.1.md；0.7.0功能见 artifacts/delivery-0.7.0.md；自动建议和拖动排序见 artifacts/delivery-0.8.0.md；本版首页显示区域调整见 artifacts/delivery-0.8.1.md，按用户要求不运行测试。
