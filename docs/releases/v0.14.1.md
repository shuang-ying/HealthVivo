# 活力记录 v0.14.1 · 预发布

手机记录饮食、运动、步数、体重和体脂率，计算热量参考及 AI 吃饭／锻炼建议；手表通过**原生 BLE 直连**展示手机数据与日期历史。
本版起仓库只有两个安装包，不再包含任何扩展程序。

## 配套安装包

| 软件 | 版本 | 安装文件 |
|---|---|---|
| Android 手机 App | 0.14.1（versionCode 23） | vitality-phone-0.14.1.apk |
| BlueOS 手表 App | 0.7.1（versionCode 15） | health-vivo-watch-0.7.1.rpk |

请配套更新两个软件。手机 APK 直接安装；RPK 可继续用第三方 OrbitV 应用安装，它只作为安装器，不参与运行。
已有健康记录、AI 配置与手表日期缓存保留。

## 本版改动

**手机与手表的蓝牙连接重写为持久化直连。**

- 单特征 GATT 读写，20 字节带响应写入，不协商 MTU、不使用通知；沿用已在真机验证过的拓扑。
- 分帧传输加入整包 CRC-32，损坏或乱序的分段在解密和存储之前就被拒绝；回复正文按段拉取，
  手表不会无界缓冲；新增一次性加密往返的“连接自检”。
- 首次连接自动登记 32 字节凭据，手机用 Android Keystore 包装保存，手表存在应用私有存储；
  之后每次重连自动认证，无需输入配对码。
- 手机前台服务持有连接，失败按 1、2、4、8 秒递增重试（上限 30 秒）；手表端有 3 秒周期的广播看门狗，
  无人连接时重新请求广播、服务失效时重建服务。手表会话失效时手机在同一条链路上重跑握手，不重建物理连接。
- 手动更新请求先落盘，断线、应用重启或手表重启后继续。

**移除了 OrbitV 扩展方案。** 扩展工程、手机端桥接、手表端内置 SDK、脚本与文档已整体移出代码树，
新版 APK 中不含任何相关类或字符串。旧扩展源码存档在本机不纳入版本管理的 `archive/orbitv-extension-1.2.0/`。

**README 与文档按两个应用重写**，并记录了两条真机踩出来的设备侧事实。

## 真机验证

在 vivo X80 与 iQOO WATCH GT2 / BlueOS 3 上完成验证：

- 连接建立、服务发现（7 个服务，含本应用服务）、凭据认证（已登记，无需重新登记）；
- 加密读取手表日期索引 → 逐日加密下发 → 手表逐个回 SAVED → 手机记录完成，界面显示“手表已确认保存 N 个更新日期”；
- 缓存修复后的两次普通重连均在首次服务发现时找到服务。

单元测试：手表协议 40 项、手机 JVM 49 项。

## 当前适用范围与已知限制

- 附件 APK 是**调试签名**构建，包含调试入口，不是应用商店发行包，不要作为长期发行签名依赖。
- 尚未验证：传输中途强制断线后的续传、熄屏/长期后台的持久性、以及真实无线链路上的首次登记
  （本次验证走的是已登记凭据路径）。
- 首次登记仍是首次使用信任，此阶段不能声称抵抗中间人或附近其他客户端抢先登记；本版未读取任何 vivo 健康数据。
- **Android 会按已配对设备缓存服务目录。** 若手机一直提示“未发现活力记录直连服务”，
  请在系统蓝牙设置里对这台手表**取消配对再重新配对**（关闭再打开蓝牙不足以清除，也没有公开 API 可清）。
- **从 0.12.3 / 0.5.3 直接升级**的机器没有可用的按天版本账本，第一次同步会把手机里所有日期重发一遍：
  不丢记录、不重复入库，只是这一次传输量较大；从 0.13.x 升级不受影响。
- 系统回收或挂起仍可能中断连接；手表是只读看板，不修改手机记录。

详细说明见源码中的 `docs/LINK_PROTOCOL.md`、`docs/LINK_IMPLEMENTATION.md`、`docs/WATCH_GUIDE.md` 与 `README.md`。
