# 活力记录 v0.15.0 · 预发布

手机记录饮食、运动、步数、体重和体脂率，计算热量参考及 AI 吃饭／锻炼建议；手表通过原生 BLE 直连展示手机数据与日期历史。
本版把「消耗」拆开写清楚来源，把步数与运动的重叠改成减法去重，并给两端加上趋势直方图。

已有健康记录、AI 配置与手表日期缓存保留。

## 本版改动

**能量来源写清楚。** 首页能量卡片的两个数字都可以展开：每日消耗＝静息代谢＋运动＋步数（步数已去重），
当天登记摄入＝早餐／午餐／晚餐／加餐，每一行都标出它的口径。

**步数与运动的重叠改成减法，不再是「取较大值」。**

```
运动步数   = 已勾选且填了步数的运动之和（超过当天总步数时按总步数截断）
记录步数   = 总步数 − 运动步数（不小于 0）← 步数消耗按这个算
活动净消耗 = 步数净消耗 + 每条运动各自的估算
```

现在同一次跑步不会既按整段步数算一遍、又整条计一遍：总步数里的那部分先被扣掉，只对剩下的记录步数算步行消耗，
运动保留自己的估算。界面会显示拆分，例如「总 10000 步（运动 3000 + 记录 7000）」，手机与手表措辞一致。

**记录运动时，时长、距离、组数是三个都可留空的输入**，不再三选一，公式按实际填了什么自动选择
（同时填了时长与距离时，步行和跑步优先按距离）。勾选「已包含在当天总步数中」后可以填写本次大约多少步，
留空时可让 AI 估算；**只勾选不填步数时按未包含处理**，因为本机公式不产生步数，没有可减的量。

**新界面。**

- 饮食页与运动页的标题旁各有一张总计卡片；运动页的总计**含步数**，等于该页步数卡片与各张运动卡片之和。
- 运动页顶部有当天步数卡片，像运动记录一样给出步数净消耗，但不计入运动记录条数。
- 趋势页新增一张卡片，内含饮食 / 运动 / 热量剩余三个直方图，用标签切换，并给出合计、日均和最近 7 天的数值。
- 手表端同样显示步数拆分，并有同款的三个直方图，数据来自手机随当天摘要下发的最近 14 天序列。

**数据与契约。** 本机数据库 4 → 5，只给运动表增加可空的「本次运动步数」列，旧记录该列为空并按未包含处理。
当天摘要新增步数拆分、能量构成与 14 天趋势字段。

## 验证状态

单元测试：手机 JVM **67 项**、手表（含手机快照契约）**57 项**，两端均重新构建通过。

手机与手表是两个程序、两种语言，最容易出的错不是编译失败而是字段悄悄对不上。因此有一份共享的契约固定样本：
手机端测试用它真实产出的 JSON 断言 `watch/test/fixtures/snapshot-v1.json`，手表端测试把同一文件喂给手表自己的
校验器与行构造器；任一端改名或改类型都会让其中一个测试变红，而不是让手表静默丢掉一整天的数据。

**真机状态：** 链路与协议本身在 0.14.1 / 0.7.1 上做过完整验证（X80 + GT2）。本版只增加了界面、热量口径与数据库列，
链路未改，**但这些新功能尚未在真机复测**，数据库 4 → 5 的覆盖安装也还没有在装有版本 4 数据的设备上跑过。

## 当前适用范围与已知限制

- 附件 APK 是**调试签名**构建，包含调试入口，不是应用商店发行包，不要作为长期发行签名依赖。
- 尚未验证：覆盖安装到版本 4 数据库后的迁移、新字段的实机同步、两端新直方图的实机渲染、
  传输中途断线后的续传、熄屏/长期后台的持久性，以及真实无线链路上的首次登记。
- 首次登记仍是首次使用信任，此阶段不能声称抵抗中间人或附近其他客户端抢先登记；本版未读取任何 vivo 健康数据。
- **Android 会按已配对设备缓存服务目录。** 若手机一直提示「未发现活力记录直连服务」，
  请在系统蓝牙设置里对这台手表**取消配对再重新配对**（关闭再打开蓝牙不足以清除，也没有公开 API 可清）。
- **从 0.12.3 / 0.5.3 直接升级**的机器没有可用的按天版本账本，第一次同步会把手机里所有日期重发一遍：
  不丢记录、不重复入库，只是这一次传输量较大；从 0.13.x 升级不受影响。
- 步数消耗仍按平地步行估算，不扣除坡道、负重或越野差异；「记录步数」里也包含运动之外的步行。
- 系统回收或挂起仍可能中断连接；手表是只读看板，不修改手机记录。

详细说明见源码中的 `README.md`、`docs/CALORIE_MODEL.md`、`docs/LINK_PROTOCOL.md`、`docs/LINK_IMPLEMENTATION.md` 与 `docs/WATCH_GUIDE.md`。
