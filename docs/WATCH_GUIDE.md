# 手表应用使用说明

当前开发配套：Android 活力记录 **0.15.0**、GT2 / BlueOS 3 活力记录 **0.9.0**。本版直接通过原生 BLE 通信，不需要 OrbitV 扩展程序和手动配对码。链路已在真机（X80 + GT2）验证完整同步保存确认；本版新增的日历趋势图、能量逐项展开与手表端周／月／年口径尚未在真机复测。手表协议与摘要契约测试 77 项、手机 JVM 测试 87 项通过；长期后台表现待验证。**这一版两端必须一起升级**：摘要结构升到 schema 3，旧版手表读不了新摘要。首次连接与实现细节见 [手表直连实现](LINK_IMPLEMENTATION.md)，协议见 [活力直连协议 v1](LINK_PROTOCOL.md)。

之后使用时覆盖更新两个安装包，保留正式应用与记录。手机 APK 可直接安装；手表 RPK 可继续用第三方 OrbitV 应用安装，
它只作为安装器，同步运行不需要打开它。

1. 打开手表“活力记录”，保持页面可见，确认主页底部显示“直连服务已开启”。
2. 手机“我的 → 手表直连”允许附近设备权限，点击“搜索手表”，选择 GT2。
3. 连接信息由手机自动生成并在两端保存，之后重连无需输入；手机前台服务维护持续连接，手表端广播看门狗负责让手机随时能重新连上。切换手机时，先关闭旧手机连接，再在手表“连接管理”清除旧手机连接，健康记录保留。
4. 手机点击“更新到手表”，或手表主页点击“获取更新”。两端保存确认后才显示完成。已有请求在断线、应用重启或手表重启后都能继续，不因重连创建新请求。
5. 需要确认链路是否正常时，可在手机点击“连接自检”，它会向手表发送一次加密往返并回显结果；自检不传输任何健康记录。
6. 手表日期箭头切换前后一天；点击日期选择缓存日期，离线也可查看。
7. 点“三餐”进入早餐、午餐、晚餐卡片，再进入某餐查看食物。二级页面保留内容和返回入口；更新按钮只在主页最底部。
8. 点“趋势”进入趋势图。饮食（摄入）／运动（活动）／热量剩余三张图都支持**周／月／年**：周是这一周的七天（横轴标一到日），月是这个月的每天，年是这年的十二个月；< 和 > 按当前粒度翻到前一段、后一段（没有比当前更晚的一段），走开后出现“回到当前时段”。
   - 每张图都有**纵轴范围**（柱状图从 0 起算，热量剩余的负值画在 0 线下方；体重与体脂的范围贴着实际读数、不从 0 起算）。
   - **点任意一列**查看它的日期与数值；正在查看的那一列有 ▼ 标记，图下方也会列出最近几列可以直接点。
   - 另有**体重**与**体脂率**两张趋势图，同样支持周／月／年与翻页，只有测量的日期才有点。
   - 正在查看的日期由主页的日期箭头决定，趋势图打开时停在那一日期所在的时段。当天没有趋势数据时，页面提示在手机点击“更新到手表”，不画空图。

能量卡片的红绿差值只等于当天消耗参考减当天登记摄入；正值绿色，负值红色。主页步数在手机提供“已计入当天总步数”的运动步数时，第二行显示“运动 x + 记录 y”的拆分；没有运动步数时仍是单独一行总数。体重/BMI 与体脂率数轴沿用手机提供的范围，不自行从 BMI 推算体脂率。手机每日步数仍由用户按天录入。

手机健康记录、AI 配置与手表日期缓存保留。旧缓存缺少数轴时，应在完成配对后主动更新；资料不适用时显示原因。系统回收或挂起手表应用时连接可能中断，长期熄屏表现尚待本版实机验证。蓝牙连接恢复不触发新的健康记录同步。

旧扩展方案（OrbitV ovpkg）已废弃，历史说明与源码存放在不纳入版本管理的 `archive/orbitv-extension-1.2.0/`。
旧通信探针 `com.lrh.healthvivo.watch.directprobe` 使用另一个服务 UUID，与本版互不干扰，也可以直接卸载。
升级到本版后需要一次首次连接（手机搜索并选择手表，无需输入代码），因为旧协议的凭据不会被当成新协议的凭据；
手表按天缓存原样保留，历史日期不需要重新同步。

如果手机一直显示“未发现活力记录直连服务”，那是 Android 按设备缓存了过期的服务目录：
在系统蓝牙设置里对这台手表取消配对再重新配对即可，关闭再打开蓝牙不够。
