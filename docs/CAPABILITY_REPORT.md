# 手机分析版：数据来源可行性

核查时间：2026-10-12。范围仅 Android 手机；手表开发暂停。

更新：用户登录 Health Kit 后台时收到个人账号无法登录的提示。个人账号本地接入目前不能按原路线推进，替代方案见 [LOCAL_IMPORT_FEASIBILITY.md](LOCAL_IMPORT_FEASIBILITY.md)。此前的申请草稿保留供咨询使用，并不表示已具备准入资格。

## 官方依据

- [Health Kit 平台简介](https://developers.vivo.com/doc/d/bb71c60ceaf645b7af51a4365a5676bb)：2026-09-09 更新，说明提供本地与云端 API，基于用户授权和应用接入审批。
- [开发者注册介绍](https://developers.vivo.com/doc/d/fe1c4a7379334f508fcbc5345db88493)：需在 Health Kit 平台创建应用、开通相应数据权限。与智能终端互联服务分别申请。
- [云接口文档](https://developers.vivo.com/doc/d/4ea8ba1ec4cd44bd8bdaca9f3fecf795)：2026-09-09 更新，已公开步数与运动记录接口。云方式要求服务端接入和官方配置；FAQ 明确不支持客户端直接接入。

## 当前边界

| 数据 | 已确认的公开能力 | 本次手机接入状态 |
|---|---|---|
| 每日步数 | 云接口已列出 | 用户选择本地路线，本地资料与权限待取得 |
| 运动记录及记录内千卡 | 云接口已列出 | 解码模块已实现；本地读取待接入 |
| 健康减脂饮食 / 食物照片 / 点数 | 本次查到的公开接口未列出 | 待官方确认，不能保证能读取 |
| 身高 / 体重 / 体脂 / 全天消耗 | 本次查到的公开接口未列出 | 待本地字段文档与权限确认 |

“未列出”不等于不存在；也不等于已开放。智能终端 device-rpc.aar 的作用是应用与手表之间通信，不能据此取得 vivo 健康数据库读取权限。

## 已实现的手机代码

概览、近七日趋势、运动/饮食记录、本机数据管理；带来源和同步时间的独立 Room 存储；有效运动千卡小计；来源食物热量优先，若仅提供份量和能量密度则按克数计算；缺失值、异常记录、重复 ID、权限撤销、账号切换和旧同步结果处理。

日活动热量若可读，不与运动记录或步数再次相加。仅有运动记录时不能求全天总消耗。每日缺口必须同时具备完整饮食、完整全天总消耗，且该日已经结束。当前没有足够数据产生个人摄入目标或训练强度建议，建议模块以记录覆盖与数据质量为依据，不伪造目标。

步数和运动的解码依据云文档；食物、体重与全天消耗的数据类只是本应用内部分析模型，不代表存在对应 vivo API。生产数据源目前明确返回“未接入”。APK 不包含样例健康数据，不采集运动、不读取其他应用私有目录、不调用云服务。

旧原型源码保存在 archive/phone-tracking-0.1，不参与新 APK 编译。分析版使用独立 vivo-health-analysis.db，不读取旧 health-vivo.db，也没有主动删除旧库的代码。本次安装后只查到新的分析库，不能确认之前原型的本机缓存仍然存在。

## 后续接入验收

取得本地 SDK 与批准权限后，实现 HealthDataSource，逐项核对手机原记录、热量单位、历史查询范围与更新时间。不能将不完整查询标记为完整快照；权限查询失败不清空缓存，已确认撤销权限则清除相关分析数据。核对修改/删除、异常记录、跨日运动、多设备合并与账号切换，再允许页面显示真实数据。

资料申请草稿见 [HEALTHKIT_LOCAL_REQUEST.md](HEALTHKIT_LOCAL_REQUEST.md)。尚未代你提交提单。
