# OrbitV 手动同步与日期历史

配套：手机 **0.12.3**、BlueOS 手表 **0.5.3**、OrbitV 扩展程序 **1.2.0**。扩展程序是 `.ovpkg`，与底层驱动 `.orbitpkg` 不同。旧版 0.4.1 的 GT2 全链路同步已经由用户确认成功；本次沿用页面直接初始化 SDK 的方式。

## 更新与使用

1. 覆盖安装 `artifacts/vitality-phone-0.12.3.apk`。
2. 使用 OrbitV 安装 `artifacts/health-vivo-watch-0.5.3.rpk` 到 GT2。
3. 使用 OrbitV 安装 `artifacts/vitality-orbitv-1.2.0.ovpkg`，重新打开“活力记录同步”。三者需配套更新，避免旧协议与新接口混用。
4. 手机“我的 → 通过 OrbitV 同步手表”开启持续连接。已有首次配对信息无需重新复制；新用户复制后在扩展程序粘贴保存。不要把配对信息发到聊天或日志。
5. 保持 OrbitV 扩展程序和手表活力记录在前台。手机“更新到手表”会保留本机接口、排队更新指令并切换到 OrbitV；如未进入扩展程序，请手动打开它。
6. 点击手机“更新到手表”（扩展程序也有同名按钮），或者点击手表“获取更新”。完成后手表显示确认已回传，手机显示已确认完成。

录入、修改、删除饮食和运动，或者 AI 建议完成时，不会传输健康数据。手表打开页面、切换日期也不会读取新的健康摘要。前台定时检查仅读取更新指令及确认状态；检测到用户主动点击手机更新所留下的新指令后才开始传输。尚未执行的主动更新指令可以在下次打开手表时执行；失败保留指令以便重试。

本机接口不再主动在 15 分钟后关闭；重复开启不会中断正在传输的套接字。开关状态保存在手机，系统回收进程后请求恢复服务；系统超时停止后，用户回到手机 App 时恢复。手动关闭后不会自动恢复。手表已保存的日期继续离线可查；不需要 vivo 健康、官方账号或云服务器。

## 按日期增量更新

手机从一次一致的本地快照构建每个日期的显示摘要，用内容哈希维护稳定版本。手表先发送已有日期版本列表；手机只返回缺失或版本不同的日期。无变化时不传输日期记录，不重新写日期缓存。每个变化日期传输完整显示摘要，而不是整库覆盖；删除记录也会使该日期摘要更新。

首次更新包含手机已有记录日期和今天。手表缓存中的历史日期保留，手机查询也包含手表已有日期，避免删除最后一条记录后留下旧内容。分页会话固定本次摘要，单页最多 12 个日期，通常控制在 48 KB 内容以内；单个日期上限 96 KB。最大日期索引 5000 条。

手表将新版本写入独立日期键，再提交日期索引，成功后才发送精确的批次回执。写入或索引提交失败时保留此前可读缓存；重复版本不重新写入日期内容；相同版本但内容冲突、旧版本或格式无效均拒绝。旧 `fitness.dashboard.v2` 缓存可迁移读取，不清空原缓存。分页全部确认后才标记手机指令已处理。

日期箭头与日期列表查询只读取已同步的本地历史。当前日期没有缓存时显示未同步，而不是套用其他日期的记录。

## 界面

- 扩展程序页面本身可以上下滚动，适应外层固定高度的 OrbitV 容器。
- 启动图标改为透明底圆形紫色图标，保留白色 V 标识；由源 SVG 生成 PNG，构建时自动渲染。
- 手表卡片宽 396，左右边距各 18，恢复 0.5.0 的全屏列表和尺寸：正文宽 360，仅将文字居中；删除上下 56 的固定留白，长建议仍分段滚动。
- 同一卡片列出消耗与登记摄入。差值仅为当天消耗参考减登记摄入，正值绿色、负值红色；未登记食物的合计为 0，消耗缺少适用资料时保持未知。目标体重不参与差值计算。
- AI 页面只显示吃饭建议和锻炼建议；手机仍发送身体资料、目标、当日餐食与运动，提示词要求简短具体的食物份量与适度训练安排。
- 手表三餐入口只列早、午、晚餐卡片；进入某餐才显示食物。原加餐记录继续可查。
- 更新按钮、连接状态和版本信息只在手表主页面最底部显示，所有二级页面隐藏此区域。
- 手机和手表显示相同的 BMI、体脂率颜色数轴与当前值箭头；手机依据适用资料生成同一套范围后同步给手表，未适用时不绘制成人评级轴。
- 手机 BMI 超出范围时显示到 18.5／23.9 参考边界所需的增减重，向上保留 0.1 kg；BMI 正常不显示该提示。体脂率仅来自用户测量，按已有年龄／性别参考范围绘制黄色、绿色、红色数轴。
- 实验 BLE 连接入口和手表 BLE 功能已移除；当前传输由 OrbitV 负责。

## 数据路径与本机接口

Android Room／建议缓存 → 绑定 `127.0.0.1:28341` 的持续本机接口 → 同手机 OrbitV 扩展程序 → OrbitV 蓝牙网关 → 手表 SDK → 格式校验 → 本地日期缓存 → 回执原路返回。

传输步数、体重／目标、BMI、用户录入的体脂率、热量参考、运动、三餐与已有建议。每餐与运动列表最多显示 20 项，超出数量提示在手机查看。不发送照片、完整个人资料、数据库文件或模型 API 密钥。第三方 OrbitV 可访问这些显示摘要；本扩展程序持久保存配对配置，不额外保存健康摘要。

接口使用 App 生成的 256 位令牌，拒绝无令牌请求。配对地址严格限定同手机回环地址，不能指向局域网或云服务器。接口为 `POST /heartbeat`、`GET /control`、`POST /request`、`POST /sync`、`POST /saved` 和 OPTIONS，旧 `/snapshot` 已关闭。`/control` 和 `/heartbeat` 只含更新指令、确认时间、连接状态及软件版本；只有 `/sync` 读取健康摘要。回执必须精确匹配本次批次日期与版本。服务仅由用户开启，不注册开机自启。连接心跳 20 秒失效；手动停止或系统暂停后关闭套接字。日期传输会话仍限时 15 分钟，与连接存活时间分开。

## 持续连接的边界与检测

- 扩展程序每 5 秒分别检查手机本机接口与 `ov.watch.getInfo()`。手机接口异常不会掩盖手表状态，任一失败清除旧就绪状态。
- 手表页面可见期间每 3 秒通过 `POST /api/control` 发送版本心跳；手机展示扩展程序、蓝牙通道、手表应用三段状态，20 秒无心跳即失效。
- 手表每次请求健康摘要和发送保存确认前，扩展服务重新检测通道；失联时不转发摘要。扩展程序更新按钮还要求最近的手表应用心跳。
- 手机点击更新可留下待执行指令，双方恢复后执行这次主动请求。单纯重新连接、录入、打开页面、切换日期不会生成新更新指令。
- OrbitV 文档明确服务只在扩展程序打开期间运行；退出页面后停止新请求。自动重连不能让已关闭的 OrbitV 扩展程序常驻。手表隐藏页面时也停止业务轮询，返回后恢复。
- Android 15+ 对后台 dataSync 前台服务有累计运行时限；本应用遵守 onTimeout 并停止，保留开启偏好，回到 App 时恢复。没有更改服务类型或绕过限制。

## 数轴显示排查

用户确认 GT2 运行 0.5.2，但“无法连接手机端开发者接口”；因此最新数轴描述可能尚未进入旧缓存，尚不能认定为纯绘图问题。

0.5.3 给卡片与色段、刻度分别使用具名循环变量，为数轴容器设明确高度，并区分含数轴卡片的列表类型；保持 0.5.0 的整页与卡片宽度。旧缓存没有数轴字段时明确显示“参考数轴尚未同步，请获取更新”，不会按未知年龄或性别编造范围。字段为空时说明资料不适用。

手机与手表及扩展包配套更新后，开启持续连接，等待三段就绪，再手动获取更新一次。BMI 轴需成年适用资料；体脂率轴需适用的年龄与性别参数，箭头只对应用户上传的测量。

## 构建

```powershell
./scripts/build-android.ps1
./scripts/build-watch.ps1
./scripts/build-orbitv.ps1
node scripts/simulate-orbitv-connection.mjs
./scripts/prepare-watch-studio.ps1 -Demo
```

`build-watch.ps1 -Install` 仅把 RPK 复制到手机 Download，随后通过 OrbitV 安装。BLE 历史研究工具不属于当前运行路径。`simulate-orbitv-watch.mjs` 与被它驱动的 `orbitv-sync.mjs` 已在 0.7.1 随直连协议重写一并删除；OrbitV 现在只用于把 RPK 安装到手表。
